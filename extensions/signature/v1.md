# A2A per-message signature extension, v1

Extension URI: `https://algovoi.co.uk/a2a/ext/signature/v1`

A minimal, wire-format-only, non-hosted per-message signing layer for A2A. It lets
a receiver cryptographically verify that a specific request came from the holder
of the claimed key. It is orthogonal to AgentCard signing (A2A spec 8.4, which is
JWS over the card document) and composes with it: the 8.4-signed card declares
this extension and carries the agent keyid.

This document describes the wire format. It is byte-compatible with the proposal
in a2aproject/A2A#1829; an implementation that verifies one verifies the other.

## 1. Declaration and activation

- An agent declares support in its AgentCard `capabilities.extensions` as an
  `AgentExtension` with `uri` = the extension URI above (A2A spec 4.2 / 4.4.4).
- A client activates it per request via the `A2A-Extensions` header carrying the
  extension URI. Activation is an unsigned opt-in hint, not a security control;
  the signature is the control.

## 2. Algorithm and format

- **Algorithm:** Ed25519 (RFC 8032). `alg="ed25519"`. A verifier MUST reject a
  signature whose `alg` parameter is absent or outside its allow-list.
- **Format:** RFC 9421 HTTP Message Signatures with RFC 9530 Content-Digest.
- **Covered components:** `("@method" "@path" "content-digest" "created")`.
- **Signature parameters:** `created` (required), `keyid` (required), `alg`
  (required), `tag` (required, value `a2a-signature-v1`), and OPTIONAL `nonce`
  and `expires`.
- **Content-Digest:** `sha-256` over the exact `application/a2a+json` body bytes
  as sent. A verifier MUST compute the digest over the raw received bytes and
  MUST require `content-digest` to be a covered component.
- **`tag`:** the fixed value `a2a-signature-v1` binds the signature to this
  extension and prevents cross-protocol reuse. It is covered via
  `@signature-params`, so it is part of the signed bytes.

## 3. keyid resolution

`keyid` is a self-resolving identifier. A verifier resolves it to an Ed25519
public key across three sources, and SHOULD record which was used:

- `did:key:z...` (inline, self-certifying, no network),
- a cached key,
- an HTTPS resolver: a `did:web` DID (resolved to its `did.json`) or a plain
  `https` URL returning either a W3C did.json or `{ "address", "public_key" }`.

The resolver MUST be SSRF-guarded: https only, resolved addresses screened
against a non-public blocklist (private, loopback, link-local including cloud
metadata), the connected peer IP re-checked after connect (DNS-rebind defence),
redirects re-validated and capped, and size and time caps.

Resolving a key proves nothing about identity on its own. Which keyid is
legitimate for a given agent is a policy binding the verifier owns, normally via
the agent AgentCard. A verifier MUST NOT trust an arbitrary attacker-chosen
keyid.

## 4. Freshness and replay

- A verifier SHOULD enforce a `created` freshness window (this reference uses a
  300 second maximum age). Only covered `created` / `expires` are trusted.
- For true single-use, a verifier maintains a seen-set keyed by `(nonce, keyid)`
  and rejects a repeat.

## 5. Signing base (RFC 9421 section 2.5)

One line per covered component, then `@signature-params` last, `@method`
case-preserved. The signature is Ed25519 over the UTF-8 bytes of this base.

## 6. Worked example (reproducible)

Ed25519 key from RFC 8032 section 7.1
(`public_key = 700e2ce7c4b674427eab27ba820bcf6f0faebe68e09fe8564292114e41dc6a41`),
so `keyid = did:key:z6MkmzgF8XmXcQnJ4ZiCv2rXfAz1njvvTXWtqFhgFmHaAQCG`.

Request: `POST /a2a/rpc` on `api.algovoi.co.uk`, `created = 1778955520`, body:

```
{"jsonrpc":"2.0","id":1,"method":"message/send","params":{"message":{"role":"user","parts":[{"text":"hi"}]}}}
```

Headers:

```
Content-Type: application/a2a+json
A2A-Extensions: https://algovoi.co.uk/a2a/ext/signature/v1
Content-Digest: sha-256=:8hUsBzUbG1vnvJXJSp9pSlFkoRwrH+lLyxZ+AWtWX/4=:
Signature-Input: sig=("@method" "@path" "content-digest" "created");created=1778955520;keyid="did:key:z6MkmzgF8XmXcQnJ4ZiCv2rXfAz1njvvTXWtqFhgFmHaAQCG";alg="ed25519";tag="a2a-signature-v1"
Signature: sig=:6r+DyCYjlm2dCJgLq8eTuk0G/zO2K2AfBSUHJ5LPPkC9AlNzYR5iFoS/R4vhrtLbMp4ogwHpySo+GBoEpz8lDQ==:
```

Signing base:

```
"@method": POST
"@path": /a2a/rpc
"content-digest": sha-256=:8hUsBzUbG1vnvJXJSp9pSlFkoRwrH+lLyxZ+AWtWX/4=:
"created": 1778955520
"@signature-params": ("@method" "@path" "content-digest" "created");created=1778955520;keyid="did:key:z6MkmzgF8XmXcQnJ4ZiCv2rXfAz1njvvTXWtqFhgFmHaAQCG";alg="ed25519";tag="a2a-signature-v1"
```

Reference implementation: `algovoi-rfc9421-a2a` over `algovoi-rfc9421-signer`,
`algovoi-rfc9421-verifier`, and `algovoi-rfc9421-keyid` (all Apache-2.0, PyPI).

## 7. Host binding (note)

`@authority` is deliberately not covered by default, so the signature survives a
proxy that rewrites the authority. A deployment that needs the signature bound to
a target host adds `@authority` to the covered set.
